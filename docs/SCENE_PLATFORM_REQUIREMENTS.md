# 层知 · Anatolume 可扩展人体场景平台需求方案

版本：V1.0  
编制日期：2026-10-16  
文档状态：需求方案，供后续设计、开发和验收使用  
适用范围：网页、Windows、macOS，以及后续 Android 客户端

## 方案摘要

层知拟在现有三维人体图谱基础上，建设可扩展的人体场景平台。平台统一提供模型查询、展示控制、标注、步骤编排、互动、存储交换和开发接口，允许用户围绕自身需求制作、开发和分享场景。

前期以课堂教学与培训、运动与健身知识讲解、家庭与青少年科普、科普内容制作、医患及康复沟通五类场景检验基础能力的完整性。五类场景共同参与底层设计；各行业的完整课程、内容库和业务系统由后续场景作者或合作方建设。

首个建设重点是形成“可编程控制、可保存恢复、可导入导出”的基础闭环，随后完善可视化创作与互动。接口、场景格式和跨平台边界应在前期确定，云端服务和执行外部代码的插件机制分阶段建设。

本文中的“应”“必须”为相应阶段的验收要求；“预留”表示须明确数据或接口边界，不代表提前实现完整功能。性能数值为建议验收目标，需在技术设计阶段确定参考设备后冻结。

## 一、建设背景与总体目标

### 1.1 现有基础

根据当前仓库代码与项目文档，应用已具备男女模型切换、中英文结构检索、系统与结构显隐、局部观察、镜头控制、拆解、中文结构说明、离线桌面使用及更新等基础能力。模型来源、许可和女性学习模型的范围限制已有记录。

当前页面主要在 `app/page.tsx` 组织界面和交互状态，`app/scene.tsx` 承担三维渲染、模型加载和镜头等工作；部分数据与算法已拆分到 `app/core/`，平台桥接放在 `client/`。已有浏览器工具入口提供有限的查找与选中能力，可作为接入新公共接口的调用方。

上述为代码与文档层面的现状，不代表已完成所有设备的验证。当前尚未形成完整的用户场景格式、通用场景运行时和创作流程；Android 原生安装包不作为现有交付能力。

### 1.2 产品定位

建设一个面向人体知识表达和交互的基础平台，使用户能够基于统一的人体能力组织自己的展示、讲解、学习和沟通场景。

平台提供两种主要创作方式：

1. 普通作者通过可视化编辑器配置模型、视角、步骤、说明、标注和基础互动。
2. 开发者通过公开接口、组件及运行事件，开发具有自定义流程和界面的场景应用。

现有自由探索功能继续作为基础入口，并逐步使用相同的公共能力。

### 1.3 建设目标

- **可复用：** 同一套结构、镜头、展示和标注能力能够服务五类目标场景。
- **可创作：** 无需编程即可完成简单场景，并形成可编辑、可播放的作品。
- **可开发：** 外部开发者无需修改平台内部源码，即可调用已公开能力完成基础场景开发。
- **可交换：** 场景可在不同设备间导入、导出与恢复，能够识别缺失资源和版本差异。
- **可持续演进：** 模型、场景格式和接口独立版本管理，升级后能处理旧作品。
- **可跨平台：** 人体控制和场景逻辑共用，文件、窗口、分享等平台能力通过适配层提供。

### 1.4 范围边界

本期规划包括场景基础、编辑、播放、交换、开发接口和五类验证样板。首批样板用于验证共用能力，内容规模应保持可维护。

云端账号、公开场景市场、付费交易、多人实时协作、机构管理、完整动作仿真、患者影像导入及诊疗决策等进入后续规划。前期定义其扩展位置、数据归属及能力声明方式，不提前建设完整系统。

本方案是新一轮需求规划，不构成对所有阶段同时启动开发、对外发布或专业内容已经审核的声明。

## 二、用户角色与使用方式

| 角色 | 主要目标 | 使用方式 |
| --- | --- | --- |
| 场景观看者 | 看懂内容、完成互动、再次打开作品 | 打开场景并播放，无需接触编辑工具 |
| 普通场景作者 | 将自己的讲解整理成可复用作品 | 选择结构、调整画面、添加步骤和标注、预览并导出 |
| 场景开发者 | 实现自定义交互或业务流程 | 使用开发接口、组件、事件和场景文件 |
| 内容审核者 | 检查结构引用、文字、来源与适用范围 | 查看审核信息，记录结果与修订意见 |
| 平台维护者 | 维护模型、接口、兼容性与示例 | 发布能力版本、迁移工具和开发文档 |

作者、审核者身份在离线阶段可由作品元数据记录；记录作者自述不等于平台认证。在线身份与机构权限体系在后续单独建设。

## 三、五类目标场景与基础能力映射

### 3.1 课堂教学与培训

**目标用户：** 生物教师、护理及康复培训教师、学生和培训学员。

**典型流程：** 教师课前选择结构并编排步骤，课堂投屏讲解，切换标注或隐藏名称提问，课后将场景交给学生复习。

**平台应支持：** 多步骤场景、重点高亮、标注显隐、讲解备注、展示模式、点击识别、基础题目、作品导出和复制修改。

**首批验证：** “认识膝部结构”。依据现有模型核实可用内容，展示整体、主要骨骼和已包含的相关结构，包含至少一道点击识别题。缺少的组织不以估算模型冒充已验证结构。

**后续预留：** 课程目录、班级作业、成绩导出、课程平台嵌入。题目结果先使用统一记录格式，不提前建设学校管理系统。

### 3.2 运动与健身知识讲解

**目标用户：** 健身教练、运动爱好者、瑜伽及普拉提教师。

**典型流程：** 选择身体区域，切换肌肉和骨骼，突出目标肌群，解释位置关系，保存讲解画面并提供给学员。

**平台应支持：** 按身体区域组织结构、命名结构集合、独立颜色及透明度、局部镜头、标注、讲解图文和图片导出。

**首批验证：** “认识肩部肌群”。使用静态人体展示不同层次，配合文字或附图；画面调整和镜头动画不得表述为经过验证的人体动作仿真。

**后续预留：** 动作资源类型、时间轴、播放控制和模型动作能力声明。肌肉起止点、功能、运动限制等专业内容需有来源，并由具备相应知识的人员审核。

### 3.3 家庭与青少年科普

**目标用户：** 家长、青少年、一般人体知识学习者。

**典型流程：** 从生活问题进入，按少量步骤观察人体，阅读简短解释，通过寻找结构或选择题完成互动。

**平台应支持：** 通俗标题与文字、多语言内容、有限操作模式、触屏交互、内容适龄说明、局部观察和基础互动。

**首批验证：** “食物的旅行”。通过现有器官依次展示路径关系；路径和移动标记属于教学示意，不表达未经验证的实时生理过程。

**后续预留：** 配音、字幕、阅读难度标签、主题合集和家庭学习进度。学习者无需注册即可完成本地播放；进度记录默认留在设备上。

### 3.4 科普内容制作

**目标用户：** 科普作者、教师、培训人员及图文视频制作者。

**典型流程：** 选择结构、布置画面、添加标签和箭头、调整画幅、导出图片或连续画面，用于课件和内容制作。

**平台应支持：** 干净展示模式、画幅预设、背景控制、可复现镜头、结构锚定标注、高清图片导出、作者与来源信息。

**首批验证：** “胸腔结构讲解图”。保存同一场景的整体及局部视角，分别导出横版和竖版图片，检查标注、结构和来源信息。

**后续预留：** 透明背景、批量导出、镜头序列和视频输出。导出设计需独立于编辑器面板尺寸，保留资源许可信息。

### 3.5 医患及康复沟通

**目标用户：** 使用三维图辅助解释人体结构的医护、康复人员及其沟通对象。

**典型流程：** 打开指定部位，显示相关组织，添加临时讲解标记，按预设步骤说明，必要时导出一般性结构说明图。

**平台应支持：** 快速定位、简洁展示、临时标注、展示与编辑区分、适用范围说明、内容来源、讲解结束后清理临时状态。

**首批验证：** “膝部结构沟通卡”。仅验证结构讲解、临时标注和状态清理，不包含疾病判断、个体治疗建议或患者资料。

**后续预留：** 经审核的病变模型、专业流程模板、机构内容审核和受控数据接入。若后续涉及患者资料或临床用途，应另行定义访问权限、数据保护、专业验证和适用要求，不能直接沿用普通科普场景的处理方式。

## 四、总体架构与职责边界

### 4.1 分层设计

平台按以下职责组织，实现阶段可以仍位于同一仓库，是否拆成独立发布包由实际接入需求决定。

| 层级 | 职责 | 对外边界 |
| --- | --- | --- |
| 模型与结构层 | 模型目录、结构索引、版本、关系、来源与能力 | 统一查询结果和结构引用 |
| 人体控制层 | 选择、显隐、样式、镜头、拆解、状态读取与恢复 | 类型明确的命令、查询和事件 |
| 场景运行层 | 场景校验、资源准备、步骤、互动与生命周期 | 加载、播放、跳转、退出与错误 |
| 创作与观看层 | 场景编辑器、播放器、现有探索界面 | 调用公共能力，不直接控制渲染内部对象 |
| 开发者接入层 | SDK、嵌入组件、示例、扩展能力注册 | 版本化接口与能力声明 |
| 平台适配层 | 文件、存储、外链、导出、分享、窗口 | 可检测的统一接口及平台回退 |

### 4.2 设计原则

1. 场景使用公共接口，不引用 React 内部状态、Three.js 网格对象或数组下标。
2. 场景内容与渲染实现分离；更换界面布局或绘制策略不应要求重写场景。
3. 数据型场景与可执行代码扩展分别管理；导入场景文件不自动执行作者脚本。
4. 核心流程离线可用，在线服务通过独立适配器接入。
5. 扩展按实际能力申明依赖，播放器在加载前即可判断能否运行。
6. 新能力逐步接入现有应用；原有探索、搜索、模型切换及离线流程保持可用。

### 4.3 前瞻能力的建设深度

| 未来方向 | 前期必须确定 | 后续再实现 |
| --- | --- | --- |
| 新模型与模型更新 | 模型命名空间、版本、坐标约定、结构映射与能力描述 | 外部模型加工流水线与模型市场 |
| 动作与生理演示 | 资源类型注册、播放生命周期、时间轴接口边界 | 骨骼绑定、肌肉形变、专业仿真 |
| 课程与学习记录 | 题目、作答、完成事件及本地记录格式 | 班级、作业、成绩及机构系统 |
| 云端与协作 | 作品 ID、修订版本、存储适配器、冲突识别 | 实时协作、云端权限及同步服务 |
| 第三方开发 | 稳定命令与事件、能力注册、版本协商 | 动态插件安装、扩展商店 |
| 专业沟通 | 来源、审核范围、内容用途、临时会话状态 | 患者信息、专业流程与临床接入 |

预留应落实到数据字段、接口说明和一个可运行的接入例子。无明确消费者的复杂抽象不进入首期实现。

## 五、模型与人体基础能力需求

### 5.1 结构身份与关系

| 编号 | 需求 | 阶段 |
| --- | --- | --- |
| MOD-01 | 提供模型列表、模型版本、可用结构数量、来源、范围限制和能力清单 | M1 |
| MOD-02 | 结构引用包含模型标识、模型版本及结构标识；源概念 ID 保留来源命名空间 | M1 |
| MOD-03 | 区分概念、实际几何零件和用户自定义结构集合；一个概念可包含多个零件 | M1 |
| MOD-04 | 支持名称、别名、源 ID、系统及可用身体区域查询；返回人体左右及缺失信息 | M1 |
| MOD-05 | 建立结构归属、父子关系、空间范围和集合查询接口；无法提供的关系明确标记未知 | M1 |
| MOD-06 | 模型更新提供映射与缺失报告，不因名称相近或 ID 相同就自动跨模型替换 | M1 |
| MOD-07 | 区分与模型几何绑定的引用及跨模型知识标签，允许未来构建人工确认的对应关系 | M1 定义，后续完善 |

结构集合应支持命名、增删、重命名和引用，例如“本节课涉及的骨骼”。首期集合可归属于场景，不要求建立全站公共分类库。

### 5.2 展示与操作控制

| 编号 | 需求 | 阶段 |
| --- | --- | --- |
| CTL-01 | 按结构、集合或系统显示、隐藏、隔离、恢复，并支持批量提交 | M1 |
| CTL-02 | 提供选中、取消选择、高亮及结构定位；支持仅选中可见结构等交互策略 | M1 |
| CTL-03 | 独立控制可见性、透明度、强调颜色、选中和可点击状态，明确合成优先级 | M1 基本控制，M2 完善 |
| CTL-04 | 读取与设置镜头位置、观察目标、投影参数，按结构或集合适配构图 | M1 |
| CTL-05 | 提供预设视角、平滑切换、动画取消、直接恢复及用户手势接管 | M1 |
| CTL-06 | 保存与设置拆解状态、旋转设置和底座显示；拆解是展示能力，不用于表达生理运动 | M1 |
| CTL-07 | 读取完整展示快照并恢复，明确临时高亮、悬停和加载状态是否属于快照 | M1 |
| CTL-08 | 命令支持参数校验、模型就绪判断、取消和明确错误，不允许旧模型任务覆盖新模型 | M1 |

**状态规则：** 持久展示状态、学习者临时操作、作者临时编辑状态及设备偏好分别存储。场景不得静默覆盖语言、画质和隐私等全局偏好。受观看者隐私设置限制的内容须先提示，并由观看者主动确认后显示。

**样式规则：** 基础材质、作者覆盖、教学高亮和当前选中按确定的优先级合成。退出高亮必须恢复原有样式。透明结构的拾取规则应可解释，避免看到后层却总选中前层。

**批量规则：** 同一步骤的结构与镜头变更作为一次逻辑操作应用；不得逐条触发大量渲染和中间画面。失败时返回整体结果或明确的逐项报告，不静默丢失结构。

### 5.3 命令、查询与事件

公共接口至少覆盖以下类别，具体命名在技术设计时冻结：

| 类别 | 示例能力 | 契约要求 |
| --- | --- | --- |
| 查询 | 查询模型、查找结构、读取快照、检查能力 | 无隐式展示副作用 |
| 命令 | 显隐、定位、应用快照、加载场景、切换步骤 | 返回执行结果，异步任务可取消 |
| 事件 | 模型就绪、结构选择、状态变化、步骤进入、作答、加载失败 | 包含来源、场景/会话标识及必要版本信息 |
| 生命周期 | 创建、挂载、暂停、卸载、销毁 | 清理事件、动画、临时对象和资源 |

必须区分“已接受命令”和“动画或加载完成”。订阅接口返回取消订阅方法，防止重复注册；状态事件提供批量结束边界和变更来源，避免界面与扩展互相触发循环。首期可保持单一视口，但接口应以实例为边界，避免阻碍未来双视图对照。

## 六、场景格式、资源与兼容需求

### 6.1 场景的基本组成

| 数据组 | 内容 |
| --- | --- |
| 身份与版本 | 场景 ID、修订 ID、场景格式版本、创建和修改时间 |
| 作品描述 | 多语言标题与简介、作者、标签、封面、适用人群、用途与许可 |
| 运行依赖 | 模型及版本、所需平台能力、最低运行时版本、扩展依赖 |
| 展示数据 | 结构集合、初始快照、命名视角、标注与展示规则 |
| 内容流程 | 稳定步骤 ID、顺序、正文、资源引用、互动与完成规则 |
| 内容来源 | 引用资料、模型和素材来源、修改说明、审核信息 |
| 扩展信息 | 具有命名空间和版本的扩展字段 |

场景格式、作品修订、模型版本和 SDK 版本分别管理，不能用同一个版本号代替。步骤、标注和题目使用稳定 ID，重新排序后已有引用不失效。

### 6.2 文件与资源组织

- 首期支持可阅读、可校验的 JSON 场景文件，建立配套 Schema 和示例。
- 创作阶段增加带清单的场景包，包含场景描述、封面及图片等资源；采用通用归档形式，具体扩展名在技术设计确定。
- 默认引用应用已安装的人体模型，普通场景包无需重复打包完整模型。
- 每项资源记录资源 ID、类型、路径、大小、校验信息和来源。离线必需资源与可选联网资源分别声明。
- 导出提供“离线资源齐全”和“存在联网依赖”的明确结果，不将仅包含网络地址的文件标为完整离线包。
- 包内使用相对路径；不得引用作者电脑的绝对路径。导入处理目录穿越、超限解包、错误资源类型等实际文件交换风险。
- 导入未知扩展不执行代码；允许保留扩展数据，并报告播放器无法实现的能力。

### 6.3 快照与坐标规则

快照必须足够完整，使单独打开任意步骤可获得确定的语义状态。首期优先使用完整快照；未来即使采用差量压缩，播放器对外仍需提供可解析的完整结果。

模型坐标的单位、轴向、原点及变换版本应明确。镜头保存模型空间参数与观察目标，并保存构图意图；不同画幅下可适配取景，保证目标完整，不承诺跨设备逐像素相同。

标注锚点须区分结构、模型空间点和屏幕布局位置。结构锚点记录结构引用及可用的局部位置；模型几何更新后失效的精确表面锚点必须提示重新定位，不允许悄悄漂移到其他组织。

### 6.4 兼容与迁移

1. 加载前执行格式、资源、模型和能力检查，并给出完整报告。
2. 相同主版本内保持已公开格式兼容；字段新增须提供默认行为。
3. 新格式主版本需提供迁移器、说明及原文件保留机制；迁移失败不覆盖原作品。
4. 可选结构缺失时按作者定义降级；关键结构或关键能力缺失时停止对应流程并说明原因。
5. 未知模型不能自动替换为当前模型；通过显式映射或用户确认处理。
6. 导入、编辑和重新导出时，保留能够安全保存的未知元数据，报告无法保留的内容。
7. 维护一组版本样本，作为后续兼容性验证依据。

## 七、场景创作与本地管理

### 7.1 创作流程

新建或复制模板 → 选择模型 → 调整结构和镜头 → 保存初始状态 → 添加步骤、标注及说明 → 设置互动 → 预览 → 检查 → 导出。

编辑器应复用现有探索能力，同时明确“观看”“编辑”“预览”状态。切入预览时暂停编辑，退出预览恢复编辑状态；观看过程中的临时旋转不得自动改写作品。

### 7.2 功能需求

| 编号 | 需求 | 阶段 |
| --- | --- | --- |
| EDT-01 | 从当前探索画面保存单步场景，支持命名、复制和再次编辑 | M1 |
| EDT-02 | 管理本地场景，按标题、作者标签和修改时间查找，支持删除与恢复机制 | M2 |
| EDT-03 | 添加、复制、删除、重排步骤，保存步骤标题、正文和展示状态 | M2 |
| EDT-04 | 提供标注与结构集合编辑；无编程操作即可完成基础作品 | M2 |
| EDT-05 | 编辑操作提供撤销、重做及明确的未保存提示 | M2 |
| EDT-06 | 自动保存草稿，异常退出后恢复；成功保存与失败状态可见 | M2 |
| EDT-07 | 预览各步骤及横竖画幅，检查缺失结构、资源、溢出文字和无效题目 | M2 |
| EDT-08 | 记录作者、来源、适用范围和内容审核说明，导出前提供检查结果 | M2 |

批量人体操作在撤销历史中按一次用户意图记录；加载与播放步骤不混入作者编辑历史。自动保存不得覆盖用户明确保存的可恢复修订。

### 7.3 本地作品与修订

作品身份保持稳定；复制为新作品时生成新 ID 并保留来源作品信息。导入已有作品时可选择作为新副本或新修订保存，不仅凭文件名覆盖。并发编辑或外部文件变化时提示冲突，允许分别保留。

本地索引与作品文件分离，索引损坏时能够重新扫描或重新导入。平台应提供数据位置、备份和恢复说明，卸载和更新行为不得在无提示情况下删除用户作品。

## 八、标注、图文与内容表达

### 8.1 首批标注能力

支持结构标签、点位标记、带引线的文字、箭头和简短说明卡。作者可设置所属步骤、显示条件、颜色、字号及显隐。结构标注随模型移动；固定说明卡遵循画面安全区布局。

标注需支持选中、编辑、删除和排序，能够调整遮挡时的显示策略；密集标注可折叠或逐项显示。自动避让的初期目标为减少重叠，不能通过隐藏关键信息伪装为排版成功。

测量工具属于未来能力。若后续提供长度、角度等测量，必须明确模型尺度、误差和适用范围，不能将教学模型测量作为人体个体测量结果。

### 8.2 图文和媒体

首批正文支持标题、段落、列表、图片、结构引用和来源链接，采用受控富文本或 Markdown 子集。作者输入不能直接注入可执行 HTML 或脚本。

多语言正文独立于应用界面语言；场景缺少当前语言时显示作者指定的回退语言并说明。平台不得自动把未经审校的机器翻译标记为专业审核内容。

音频、视频及动作资源在统一资源类型机制下接入。音频阶段需包含字幕、播放失败提示及离线状态；不依靠自动播放才能完成学习。

### 8.3 来源和审核

支持按作品、步骤及资源记录出处与许可，分别记录“作者自述”“待审核”“已审核”等状态。已审核内容记录审核对象、内容修订、审核者及时间；修改被审核内容后应使对应审核状态失效。

模型来源、素材来源与文字作者分别记录。场景包保留完整来源清单；图片等独立输出应能附带适合其发布方式的署名与修改说明，不能仅依赖隐藏元数据满足作者的信息需求。

## 九、步骤播放与基础互动

### 9.1 播放控制

播放器支持开始、上一项、下一项、指定步骤跳转、重新开始和退出。手动播放为默认方式，自动播放由作者配置并允许观看者暂停。

任意步骤可直接进入；场景恢复不依赖先前播放过哪些步骤。播放过程的暂停应区分流程暂停与旋转/镜头动画暂停，退出时清理全部场景临时任务。

### 9.2 操作范围

作者可配置自由观察、限制结构选择、限制步骤跳转及仅展示等模式。观看者仍应具备退出、暂停、查看来源和必要的可访问性操作。作者设置属于交互规则，不作为防篡改或保密机制。

个人旋转、临时选中和作答属于观看会话；切换步骤时按作者配置恢复该步骤状态。退出场景后提供返回原探索状态的能力。

### 9.3 基础互动规则

首批支持点击结构识别、单项选择及自主确认完成。规则采用“事件—条件—动作”结构，使用允许的事件和动作集合，设置触发次数、重入限制及循环保护。

例如：进入步骤时应用快照；点击目标结构后显示解释；答题结束后允许进入下一步。条件只读取声明的数据，不执行作者提供的任意表达式。

题目应支持多个正确结构 ID 或集合，并处理一个概念包含多个零件、左右差异、父子概念重叠等情况。答题反馈与正确答案显示由作者配置；练习进度与作品数据分开保存。

### 9.4 事件记录与隐私

完成状态、作答次数和结果可先保存在本地，并允许清除。事件格式预留输出到外部学习系统的适配接口；未经使用者授权不上传个人学习记录。

暂不建设高风险考试、防作弊或临床决策功能。若开发者接入自己的业务系统，其数据收集范围应对使用者明确展示。

## 十、开发者开放与嵌入需求

### 10.1 开放方式

| 方式 | 使用者 | 首要能力 |
| --- | --- | --- |
| 场景文件 | 普通作者与开发者 | 声明结构、画面、步骤和基础规则 |
| SDK 与组件 | 网页开发者、业务系统开发者 | 创建人体实例、查询、控制、事件、加载场景 |
| 受控扩展点 | 有自定义需求的开发者 | 注册自定义面板、动作、题型或资源适配器 |
| 隔离代码扩展 | 后续插件开发者 | 在明确的隔离和权限机制下扩展运行能力 |

场景文件从 M1 开始开放；SDK 作为内部统一契约先落地，在 M3 完善为外部开发入口。M3 的扩展点优先供开发者自行构建和部署，不等于允许用户从任意场景包安装执行代码。

### 10.2 SDK 必需内容

- 提供类型定义、输入限制、返回值、错误码、事件和生命周期说明。
- 提供运行时版本、模型能力及当前平台能力查询。
- 提供已公开 API 清单与稳定性标记，避免开发者误用内部接口。
- 提供最小运行示例、场景格式示例、加载示例、互动示例及卸载示例。
- 示例无需修改平台内部文件即可调用已公开能力；正式发布前验证许可证与分发边界。
- 说明如何取消异步任务、取消事件订阅和释放实例。
- 对变更提供迁移说明。已稳定接口弃用后至少保留两个功能版本；若存在必须提前处理的风险，提供替代路径并显式说明。

### 10.3 嵌入模式

开发者可在自己的页面中放置人体视口，选择是否使用默认工具栏和信息面板。嵌入页面的布局不应强制依赖主应用整页结构。

同页面组件由实例接口通信；跨页面嵌入如采用 iframe，应约定消息协议、请求标识、来源验证和握手流程。两种方式可分阶段交付，但协议层不暴露宿主文件系统、更新或原生权限。

### 10.4 扩展注册

扩展声明唯一 ID、命名空间、版本、依赖、所需能力和可替代行为。注册项不得覆盖平台核心命令。场景依赖未安装扩展时，播放器显示缺失项，不从网络静默下载并运行。

自定义面板、题型、资源加载器及导出器可作为未来注册点。首期先验证一个可卸载的自定义互动示例，避免一次建立覆盖所有行业的复杂插件系统。

## 十一、导出、分享与跨平台

### 11.1 导出和分享

- 场景数据导出与图片导出使用独立流程，分别返回成功、失败和限制原因。
- 图片导出支持常见横竖画幅，后续按设备能力增加更高分辨率和透明背景。
- 导出前检查标注安全区、资源完整性和来源信息；超出设备能力时提供较低分辨率方案。
- 导出的图片不包含编辑面板、鼠标悬停状态和临时调试内容。
- 分享链接由后续托管能力实现；本地文件路径不能伪装为可供他人访问的链接。
- 链接分享需保留作品修订语义，区分“固定版本”和“作者最新版本”；账号与公开库阶段再实现访问管理。

### 11.2 平台能力矩阵

| 能力 | Web | Windows / macOS | Android 目标 |
| --- | --- | --- | --- |
| 场景核心逻辑与格式 | 共用 | 共用 | 共用 |
| 浏览和基础播放 | 支持 | 支持离线 | 支持触屏和生命周期恢复 |
| 创建与编辑 | 桌面浏览器优先 | 完整创作优先 | 先播放，逐步提供基础编辑 |
| 导入导出 | 文件选择、下载等浏览器可用方式 | 原生文件适配 | 系统文件及分享适配 |
| 本地作品存储 | 浏览器存储，提示配额与清理风险 | 应用数据目录 | 应用数据目录及可用容量提示 |
| 模型及素材离线 | 明确缓存完整性 | 使用随包或已安装资源 | 支持可取消的资源下载与完整性检查 |
| 图片输出 | 受浏览器与设备资源限制 | 提供文件保存 | 按显存和内存能力降级 |

Android 技术验证应尽早与 M1 并行，验证模型内存、触控、WebGL、文件读取和后台恢复；完整安装包发布放在独立里程碑。最低 Android 版本和设备规格需实机验证后确定。

首期不承诺手机具备完整桌面编辑能力；须保证同一场景格式和核心播放语义一致。模型或扩展能力不可用时按照场景声明降级或阻止运行，不允许无提示显示不完整教学内容。

## 十二、界面与操作要求

1. 保留现有柔和、简洁的视觉风格，作者工具按需展开，减少对模型视口的占用。
2. 观看者默认看到内容和步骤，作者才能进入编辑区；开发信息放在开发者文档和调试工具中。
3. 小屏幕采用抽屉或底部面板，核心内容可滚动；不依赖固定高度堆叠工具栏。
4. 长标题、中文标注、系统缩放及横竖屏切换均需保持可操作，关键按钮不得被遮挡。
5. 标注和交互状态不能仅依赖颜色；提供键盘操作、可访问名称、焦点反馈和减少动画选项。
6. 无法使用三维点选的用户可通过等价结构列表完成基础选择题；正文和步骤提供可阅读路径。
7. 删除、覆盖及离开未保存作品时提供明确结果和恢复路径，错误提示说明用户下一步可以做什么。

## 十三、质量、性能与数据要求

### 13.1 可验证的性能目标

以下为候选验收基线，技术设计阶段需记录 CPU、内存、GPU、操作系统、浏览器或 WebView、窗口尺寸和模型规模，并冻结参考设备。未完成实测前不写入对外性能承诺。

| 项目 | 建议目标及测量条件 |
| --- | --- |
| 基础控制响应 | 模型已加载时，单次常见显隐或高亮操作到首帧反馈的 P95 ≤ 100ms；样本不少于 100 次 |
| 步骤切换 | 资源预加载后，常见步骤切换到状态提交的 P95 ≤ 200ms；镜头动画持续时间单独统计 |
| 操作流畅度 | 参考桌面与 Android 设备在约定场景下旋转和播放目标 ≥ 30 FPS；同时记录长帧和卡顿 |
| 静止能耗 | 无动画且无交互时不持续请求渲染；后台暂停非必要三维工作 |
| 取消与切换 | 快速切换模型或场景时，旧任务不得写入当前状态；取消有可观察结果 |
| 资源释放 | 连续打开、关闭同一场景至少 20 次后，GPU 资源、监听器和定时器不随次数持续增长 |
| 规模基线 | 使用至少 50 步、100 个标注及图片资源的场景验证编辑、保存、导入和播放 |

加载速度同时报告网络下载、解压、资源准备和首帧时间，不用模拟进度代替实际状态。大资源采用渐进准备或按需加载；内存预算及导出上限按设备能力设置。

### 13.2 数据可靠性

场景保存采用可恢复写入，先写新数据并验证成功，再更新已保存版本。存储配额不足、权限失效、磁盘错误和外部文件变化都应返回明确结果。

作品、草稿、缓存、模型资源和学习会话分开管理。清理缓存不得删除用户作品；模型卸载前说明受影响的场景。云端同步引入前先保证本地备份和恢复流程可用。

### 13.3 外部内容与可信边界

场景文字、媒体、链接和导入包均按外部内容处理。链接遵循平台适配规则；内容包不能获得桌面更新、任意文件读写或原生命令权限。

包校验用于判断完整性，不等同于确认作者可信或医学正确。若后续提供签名、认证或审核标识，应分别说明其含义和覆盖范围。

默认作品中不包含个人患者资料。临时会话可一键清理，清理临时标注不删除作者已保存的教学内容。

## 十四、实施阶段与交付范围

### M0：契约设计与可行性验证

**目标：** 在编码前明确最容易导致返工的边界。

**交付：** 当前状态字段清单、公共控制接口草案、结构引用规则、场景 Schema 草案、坐标与标注约定、五场景能力矩阵、参考设备与性能测量方案、Android 最小加载验证结论。

**完成条件：** 用同一套数据设计描述五个样板；列明模型缺失项、能力缺口及阶段安排，未将专项内容需求直接写入核心控制层。

### M1：核心接口与场景交换

**交付：** 模型和结构查询、批量展示控制、镜头读写、事件生命周期、状态快照、场景校验和迁移骨架、单步场景保存/加载、JSON 导入导出、本地文件适配及最小开发示例。

**完成条件：** 用户在一台电脑保存展示状态，在另一台具备相同模型的电脑导入后恢复等价画面；示例能够通过公共接口完成全部基础操作并正确释放资源。

### M2：可视化创作与基础播放

**交付：** 步骤编辑、结构集合、基本标注、图文资源、本地场景列表、撤销重做、草稿恢复、预览、场景包交换、基础图片导出、分步播放、点击识别与单选题、来源和审核元数据。

**完成条件：** 非开发者可独立完成“创建—编辑—预览—导出—导入—播放”流程；五类场景各形成一个最小样板。

### M3：开放开发与跨平台完善

**交付：** 可独立接入的 SDK/组件、接口参考、扩展注册示例、嵌入模式、兼容报告、Windows/macOS/Web 共同验收、Android 播放客户端和文件交换能力。

**完成条件：** 仓库外的示例项目无需修改核心源码，能够实现至少一个带自定义界面和互动的场景；同一基础场景包在目标平台保持一致的结构引用、步骤和答题结果。

### M4：按使用反馈扩展

候选方向包括作品托管、分享链接、公开场景库、模板分发、账号同步、机构内容审核、音视频、动作资源及隔离插件。是否启动以实际场景需求和使用反馈决定，每项单独形成需求与验收范围。

阶段以交付和验收为边界。本方案不在缺少团队规模、设备基线及技术验证的情况下承诺具体工期和费用。

## 十六、主要风险与处理措施

| 风险 | 可能影响 | 处理要求 |
| --- | --- | --- |
| 提前为所有行业建立复杂系统 | 基础功能迟迟不能交付 | 五个小样板验证共用能力，专项业务后续扩展 |
| 把当前 UI 状态直接当开放接口 | 改界面导致外部场景失效 | 先建立公共命令与状态契约，再逐步迁移调用 |
| 混用概念、零件及模型 ID | 结构错配、题目误判 | 带命名空间和模型版本的引用，明确集合解析规则 |
| 几何变化导致标注漂移 | 讲解指向错误结构 | 锚点版本和缺失报告，失效时提示修复 |
| 场景资源不断增大 | 手机内存不足、分享困难 | 模型独立分发、资源预算、按需加载和能力降级 |
| 医学内容缺少审校 | 用户误解用途或准确性 | 保留来源、审核范围及模型限制，专业内容单独审核 |
| 导入即执行代码 | 获得超出场景所需的能力 | 声明式场景与代码扩展分离，后续插件单独隔离 |
| 云端业务过早介入 | 离线依赖增加、数据边界模糊 | 先完成本地交换，存储和同步通过适配层扩展 |

## 十七、实施前应冻结的设计事项

以下事项应在 M0 通过设计记录明确，属于实施准备工作，不影响采用本方案的总体方向。

1. 结构引用、概念/零件/集合关系及跨模型映射规则。
2. 场景格式、运行时、SDK 和模型各自的版本策略。
3. 快照范围、样式优先级、临时状态和全局偏好的边界。
4. 坐标系、镜头构图、标注锚点和画幅适配规则。
5. 互动触发机制、正确答案判定和学习记录最小字段。
6. 文件格式、资源限制、导入处理及旧版本迁移规则。
7. 参考硬件、性能预算、Android 支持范围及文件交换方案。
8. 五个样板的内容清单、模型可用性、来源及审核责任。
