# 多语言与术语维护

更新日期：2026-10-23。应用支持 `zh-CN`、`en`、`es`、`ja`、`ko`，语言菜单使用各语言自己的名称。网页和离线客户端使用相同资源，不请求在线翻译服务。

## 支持范围

| 内容 | 当前范围 |
| --- | --- |
| 界面 | 新增三种语言覆盖全部界面词条，包括首页、模型切换、图层、隐私、镜头、详情、来源、错误及更新操作。 |
| 系统 | 男女模型所用的全部 16 种系统／图层名称及系统概述。 |
| 结构 | 西班牙语、日语、韩语共用一个限定范围的常见器官、主要骨骼及左右结构词表；不等于全部 5,172 个源名称的完整翻译。 |
| 学习说明 | 三种语言提供九类器官的简要说明；其他结构明确标为系统概述。原有中文骨骼观察提示和中文阅读指南仍仅在中文界面提供。 |
| 来源记录 | 英文原名、FMA／HRA 标识及模型来源不变。未收录的结构保留英文，并在详情说明译名尚未核对。 |

本次没有导入外部完整术语数据库。结构词表与学习摘要由项目独立编写，参考下列机构的命名习惯和学习资料进行基础核对，**尚未经母语解剖专家逐条审校，也不是机构授权或认证的标准译本**。不使用自由组合的逐词翻译覆盖复杂血管、神经及肌肉分支，以免丢失方向或层级。

中文词表沿用已有覆盖全量源名称的待审校草稿。三种新增语言的结构覆盖范围应以代码中的显式条目为准，新增界面支持不能表述为全量医学术语完成翻译。

## 稳定性规则

- 用英文源名称定位显式词条，不更改模型 ID、数据层级或几何文件。
- 主名称与别名分开。西班牙语偏向稳定的解剖表达，例如 `ulna`、`fíbula`、`patela`；`cúbito`、`peroné`、`rótula` 作为常见搜索别名。
- 韩语主要骨骼采用 `넙다리뼈`、`어깨뼈` 等现代名称，兼容 `대퇴골`、`견갑골` 等常见汉字词搜索；不把两个名称建为不同结构。
- 日语只给显式条目补充假名别名。未核对的复合名称不通过中文汉字自动转换。
- 左右成对器官分别维护；主要成对骨骼仅在明确白名单内添加左右限定，西班牙语限定词保持词性一致。
- 搜索索引包含全部支持语言、别名、英文原名与源 ID。重音折叠仅用于搜索，不改变显示文字。全角字符和韩文组合字符经过 Unicode 规范化。
- 切换语言不重载模型，不重置隐私、显隐、选择、镜头或最近浏览记录。无效或无法读取的语言偏好回退简体中文。
- 权利人名称、项目名、DOI、许可证标识保持原样。动态 Release notes 按发布端原文显示，不在运行时自动翻译。

## 文件与扩展方式

| 文件 | 职责 |
| --- | --- |
| `client/i18n/locales.ts` | 语言清单、类型与搜索规范化。 |
| `client/i18n/index.ts` | 统一翻译入口、现有中文资源、偏好读取。 |
| `client/i18n/ui.translations.ts` | 西班牙语、日语、韩语界面文案，元组顺序为 `es / ja / ko`。 |
| `client/i18n/anatomy.translations.ts` | 显式结构名、别名、系统名称和原创学习摘要。 |
| `app/core/anatomy-search.ts` | 多语言搜索及别名匹配。 |
| `scripts/validate-locales.mjs` | 词条完整性、占位符、限定词、搜索及偏好回归检查。 |

修订术语时记录源 ID、原名、新译名、别名、参考版本及修改理由；涉及多义词或解剖范围时优先保留英文，待核对后再加入显示词表。

## 验证要求

1. 执行 `npm run check`、`npm run validate:locales`、`npm run validate:interactions`。
2. 构建网页、Cloudflare Pages 和客户端前端，确保语言资源离线可用。
3. 逐语言检查首页、列表、搜索、详情、关于、更新文案与移动端长文本；保留预览。
4. 用重音省略、假名、韩语别名和全角 ID 搜索；检查左右限定、女性器官及未收录术语的英文兜底。
5. 新增或修订医学说明仍需后续专业审校，自动测试不能替代术语或事实审核。
